# 模型替换与关卡扩展

## 替换前先备份

复制需要修改的 Prefab 或建立 Variant。不要修改第三方原始 FBX，也不要删除 `.meta` 文件来“修复引用”。生成器会更新 Demo 自有生成资产；精修过的关卡建议另存为新场景。

## 物品：只换 Visual

1. 打开 `flashlight / locktool / blackbox / sample / stone*` 中相应 Prefab。
2. 保留根节点和所有功能组件；删除或隐藏的范围仅限旧 `Visual` 子节点。
3. 将新模型作为 Visual 子节点，局部位置归零；用 Visual 的缩放适配米制尺寸，根节点保持单位缩放。
4. 调整根 Collider，尽量使用简化 Box、Capsule 或少量凸体。动态可抓取物不要使用非凸 MeshCollider。
5. 分别调整 `Attach Left` 和 `Attach Right`，检查握持方向。手电的光束朝向由 `Beam Origin` 的正 Z 轴决定；模型朝向不一致时只旋转 Visual。
6. 保留 `DemoProp.id`、维修工具 ID、黑匣子组件和浮力配置。只换外观，不改变任务事实 ID。
7. 双手分别测试抓取、松手、换手、使用 Trigger、碰撞和浮沉。

当前锚点与手指弯曲角是初始值，不是已经经头显校准的“完美握姿”。更细的每种物品手势可以扩展 `DemoHandPose`，现有实现主要通过 Grip／Trigger 分别控制手指弯曲。

## 手套

指定的左右模型必须分别使用 `SK_LeatherGlove` 和 `SK_LeatherGlove_left`。不要对右手做负缩放充当左手。

保留 XR 追踪所在的 `left / Right` 节点；模型在其下。`DemoHandAnimator` 只调整手指局部旋转，不移动 XR 根节点。姿态参数位于 `Settings/LeatherGloveLeft.asset` 和 Right 资产。

若骨骼命名不同，重新填写每个 Joint 的 Name、Curl Axis、Curl Degrees。不要一口气对全部骨骼加旋转：先测试一根手指的一个关节，再推广。关闭 Animator 的 Root Motion，避免与手部追踪争夺位置。

## 鱼模型

敌鱼保留根节点 NavMeshAgent、控制器、简化碰撞体和警戒提示；替换 Visual，保持游动方向为正 Z。动画使用导入模型的游动 Clip，不挂僵尸动画控制器。

两种普通鱼保留 `DeepSeaFishAI`、活动区中心和半径。原模型有游动动画，生成器会读取并建立 Controller。惊逃速度、声音和活动区域在 AI 组件配置；避障目前为前向球形探测，不等于复杂鱼群群集模拟。

## 潜艇与 Door

源 `SubMarine` 的 Door 实际是顶部舱盖。生成器会读取它的实际包围盒，建立独立 Hinge，再绑定维修目标与开启事件。

替换潜艇时必须检查：

- 新模型有没有正确的 Door 分组，分组里是否只包含应移动的网格。
- Hinge 是否在真实铰链位置；旋转轴与方向是否正确。
- 舱盖打开后，是否有另外一层艇壳 Collider 仍挡住入口。
- 主要通道至少约 1.2m 宽、2.2m 高；小螺丝、栏杆装饰不要全部生成细碎阻挡。
- 黑匣子、锁、记录屏和找回点是否位于可进入的舱内，而非夹层。
- Door Sweep Safety 范围是否覆盖开启扫过区域，玩家撤开后能继续开门。

当前自动生成采用真实网格碰撞，尚需人工简化和净空核验。不能把“找到 Door 名称”当作“潜艇已无卡墙问题”。

## 扩展关卡

最稳妥的起点是复制正式 Demo 场景或拖入一次 `CompleteDemoAssembly.prefab`。不要在已有完整装配体的场景再拖第二套玩家或全局服务。

新增分区后：更新管道／灯标、真实世界碰撞层、导航烘焙范围、AI 巡逻点、关键物品 Recovery Point、任务事实和检查点。`DemoSceneBindings` 负责明确绑定，不会在每次进入 Play 时生成第二套场景。

任务模型与逻辑分离：文档和终端通过 `DemoWorldAction.fact` 登记事实；物品通过 `DemoProp.factOnPickup` 登记首次取得；Door 和黑匣子解析座通过事件通知 `DemoFlow`。若新增主线阶段，应同时修改阶段枚举、目标文字、推进条件和存档兼容版本，而不只在 UI 写一个新目标。

## 给另一个 Codex 的交接指令

> 请先阅读 Assets/DeepSeaDemo/README_启动与配置.md、模型替换与关卡扩展.md，以及 Reports 下最新验收记录。不要假设全部功能已通过 VR 验收。保留原始第三方模型、1-VR 场景和用户脏改动；仅替换指定 Demo Prefab 的 Visual 子节点。先列出模型、功能根节点、左右握持锚点、Collider、任务 ID 和音频引用，再执行替换。保持 GUID 和既有接口。不要启用旧自动安装器，也不要用负缩放制作左手。完成后提供编译结果、引用检查、实际运行截图和未测试项目。官方 UniStorm 支持包缺失时明确记录阻塞，不擅自更换天气系统。
